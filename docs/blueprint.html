Darkroom Blueprint

Every subsystem, its governing specification, its line budget, and the external oracle that proves it correct. Plus the standard-library gaps that kill other candidates, and the one thing I will not promise you can build.

Rust · std only Est. 7,750 core + 2,000 test LOC Track F

Feasibility verdict

Nothing in darkroom depends on an unsolved problem.

Every module below implements a published, frozen, freely-available specification that has been implemented independently thousands of times. There is no research, no reverse engineering, no undocumented format, and no operating-system capability that Rust's standard library withholds. Each module also has an external oracle — a piece of software you do not control that will tell you immediately whether your implementation is correct.

That combination is what makes it not a hoax: you are never more than one test away from knowing you are wrong.

01

What Rust's standard library actually withholds

This is the audit that matters. These are the real gaps — the places where a stdlib-only project discovers at hour 40 that the thing it needs simply is not there. Each row is the gap, the workaround that stays inside std, and whether it is genuinely solved or merely survivable.

Missing from stdConsequencePure-std workaroundVerdict
Local IP address
no getifaddrs		 You cannot enumerate network interfaces, so you cannot tell the phone which address to open. Bind a UdpSocket to 0.0.0.0:0, connect() it to any routable address, then read local_addr(). UDP connect sets a peer without transmitting a packet, so the kernel reveals the interface it would route through. Falls back to a --host flag when no default route exists. Solved
Randomness
no rand		 No RNG of any kind ships in std. RandomState::new() is seeded by the standard library from the operating system's CSPRNG. Hashing a fixed value with a fresh instance extracts OS entropy. Legitimate, honest, and one of the better STDLIB.md entries you will write. Solved
Socket options
no SO_REUSEADDR		 You cannot share a bound UDP port with another process — which means mDNS on port 5353 is not reliably possible next to a running Bonjour or avahi. None inside std. Do not use mDNS. The QR code carries the raw IP and port, which needs no discovery protocol at all. Designed around
TLS No HTTPS, client or server, ever. None. LAN-only plain HTTP is fine — file inputs and form POST work over insecure origins; only camera and geolocation APIs would not. Scoped out
Memory mapping
no mmap		 Large-file random access must go through seek and read. Seek plus a hand-rolled page cache. Slower than mmap; disclose the number rather than hide it. Solved
File locking
no flock		 Two instances could corrupt the index. Lockfile via OpenOptions::create_new(true), which is atomic on every supported platform. Stale-lock detection by PID. Solved
Calendar time SystemTime gives you seconds since epoch and nothing else — no dates, no formatting, no timezones. Howard Hinnant's days-from-civil algorithm, about forty lines, converts both directions exactly. EXIF already stores local wall-clock time, so no timezone database is needed here. Solved
Crypto and compression No hashing, no DEFLATE, no zlib. Implement them. CRC32 and DEFLATE are required for PNG regardless, and both are short, frozen, and trivially verifiable against any existing decoder. Solved — and it's the point
Raw terminal input No termios, no console API. Not needed. The interface is a browser; the terminal only prints. Not applicable
One footgun worth naming now. std::hash::DefaultHasher is explicitly documented as not stable across Rust releases. Never persist its output to disk — an index written by one toolchain would silently fail to match after an upgrade. Write your own FNV-1a for the on-disk index. Four lines, and it removes an entire class of "why is my cache broken" bug.
02

The thing I will not promise

Out of scope, permanently

HEIC / HEIF pixel decoding. Do not attempt it.

The HEIF container is trivial — ISOBMFF boxes, an afternoon. The image inside it is HEVC intra-coded, and decoding that means CABAC arithmetic entropy decoding, quadtree CTU partitioning, thirty-five intra prediction modes, four transform sizes, the deblocking filter, and sample-adaptive offset. It is many thousands of lines of bit-exact, subtly-wrong-in-silence code, and it is precisely the kind of subsystem that consumes a weekend and produces grey mush.

This is the honest limitation of the photo-library idea, and you should know it before you commit, not after. If a judge points darkroom at an iPhone library shot in High Efficiency mode, the pixels will not decode.

Mitigation, which is real: the container is parseable, so HEIC files are still catalogued — date, camera, dimensions, and GPS all read correctly from the meta box, and the file appears in the timeline with an explicit "preview unavailable — HEVC" placeholder rather than vanishing. Combined with a README that states the boundary and explains why, this reads as engineering judgment. Silently dropping the files would read as a bug.

Two modules carry medium risk, and neither can strand you. JPEG decode is fiddly rather than uncertain — thousands of engineers have written one from this exact document, and a wrong implementation shows you a visibly broken image within seconds rather than failing mysteriously. The crash-safe index is a design problem with a known answer: write to a temporary file, sync_all(), then rename, which is atomic on every platform std supports.

04

Coverage against every scoring front

Functionality · 35%

A tool with a second day

One command, no configuration, no container. It answers a question people genuinely have — which of these forty thousand photos are the same photo? — and it stays installed afterwards. Reachable from any device on the network without an account.

Zero-dep craft · 30%

Twelve substitutions, none padded

Two image codecs, DEFLATE, CRC32, EXIF, resampling, perceptual hashing, Reed–Solomon, an HTTP server, a thread pool replacing rayon, OS entropy without an RNG crate, and a calendar without a date crate. Every one algorithmic rather than glue.

Code quality · 25%

Seams enforced from hour one

Fifteen modules with no cross-reaching: codecs know nothing of HTTP, HTTP knows nothing of hashing. Each independently testable. This is the criterion sprawl threatens, so the module boundary is a design constraint, not a cleanup task.

Innovation · 10%

The lid-lifting moment

A friendly photo gallery that turns out to contain a hand-written JPEG decoder. The gap between what it looks like and what it is is the innovation score.

Bonus · Reproducible Build +5

Claim it

Pin the toolchain, --remap-path-prefix, incremental off, build twice, publish both SHA-256 hashes, and state the envelope: same machine, same toolchain version. Roughly three hours for the highest points-per-hour item at the event.

Bonus · STDLIB Log +3

Claim it

Twelve non-trivial substitutions with rationales, and the same document feeds the 30% criterion. You are writing it either way.

Bonus · Package Killer +3

Claim it

sharp at roughly 7M weekly downloads leads, with qrcode near 3M and exifread, imagehash, and the whole tokio/axum server stack behind them.

Bonus · Single File +5

Skip it

At 7,750 lines a single file is a stunt that costs you inside the 25% criterion to buy points in a bonus. It also directly opposes maximising implementation. Bad trade — take the other three.

Verified on the build machine, not just researched

Everything above was an argument from specifications. On 16 August the machine itself was checked, twelve days early. Four blockers surfaced, none of them about darkroom — and every one would have cost hours at kickoff.

FoundImpact if discovered at kickoffResolution
Rust not installedAn hour of the first night gone.Installed

Reproducible build failedSilent loss of the +5 bonus, discovered at hour 68 with no time to diagnose.Solved — recipe below
The bonus was not free. Two clean builds with the textbook flags — pinned toolchain, --remap-path-prefix, incremental off — produced different binaries. The MinGW linker stamps a timestamp into the PE header. Adding -Clink-arg=-Wl,--no-insert-timestamp made two clean builds byte-identical: E2644016…866EAA56 twice. Determinism has to be hunted for; it is not a checkbox.
And one finding that validated a design decision. The machine reports seven non-loopback IPv4 interfaces, six of them 169.254.x.x link-local junk. The obvious way to find your own address — enumerate interfaces, take the first non-loopback — would have printed a QR code pointing at a dead address. The UDP-connect trick, which is the only option Rust's standard library leaves open, returns the Wi-Fi address correctly. The constraint did not force a worse solution here; it forced the right one.
06

Demo logistics that can still ruin it

None of these are engineering risks. All of them have ended demos.

  • Access-point isolation. Guest and corporate Wi-Fi frequently block client-to-client traffic, so the phone cannot reach the laptop no matter how correct your server is. Record on a home network or a phone hotspot, and test it the day before, not the hour before.
  • The firewall prompt. Windows will interrupt the first bind to 0.0.0.0 with a dialog. Accept it once before recording.
  • Terminal QR contrast. Render with explicit ANSI background colours rather than relying on the terminal's own theme, and also write qr.png to disk. Two paths to the same code costs nothing and removes a single point of failure from the most important beat in the video.
  • Photo set. Curate the demo folder in advance so the duplicate count is real and impressive. Include a genuine near-duplicate pair — the same shot at two resolutions — because exact duplicates are unremarkable and near-duplicates are the thing people cannot do themselves.
