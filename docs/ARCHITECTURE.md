# darkroom — architecture

> The engineering design. Module boundaries, the contracts between them, the concurrency
> model, the on-disk format, the costing, and the order it gets built in.

---

## 1. What it is

> **Point it at a folder of photos. Browse them from your phone. It finds the duplicates.**

A single Rust binary with an empty `[dependencies]`. It walks a directory, decodes every
image **itself**, reads EXIF **itself**, resizes and re-encodes thumbnails **itself**,
computes a perceptual hash to cluster near-duplicates, serves a web gallery over the LAN
from an HTTP server it also wrote, and prints a QR code — generated by its own
Reed–Solomon encoder — so a phone can reach it without anyone typing an IP address.

Nothing is uploaded anywhere. That is the product claim as well as the architectural one.

**Status: runner-up.** `zql` is the pick, by 0.15 composite. See `OVERVIEW.md` §6 and
`../../planning/FINALISTS.md`. This folder exists so darkroom is a decision away from
being buildable, not a week away.

---

## 2. The shape

Two programs sharing one process. The **indexer** turns files into a catalog; the
**server** turns the catalog into a website. They meet at the index and nowhere else.

```
                    ┌──────────────────────────────────────────┐
   argv ──────────► │  cli — parse, validate, exit codes        │
                    └───────────────┬──────────────────────────┘
                                    │
              ┌─────────────────────┴─────────────────────┐
              ▼                                           ▼
   ┌────────────────────────┐                  ┌──────────────────────┐
   │  INDEXER               │                  │  SERVER              │
   │                        │                  │                      │
   │  walk ─► pool ─┬─► jpeg│ decode           │  http  accept loop   │
   │                ├─► png │ decode           │   │                  │
   │                ├─► exif│ parse            │   ├─► /            web│
   │                ├─► resample ─► png encode │   ├─► /api/photos  json│
   │                │        └─► deflate       │   ├─► /thumb/{id}  bytes│
   │                └─► phash                  │   ├─► /orig/{id}   bytes│
   │                        │                  │   └─► /api/progress SSE │
   │                        ▼                  │                      │
   │                    index (write)  ◄───────┼── index (read)       │
   └────────────────────────┘                  └──────────┬───────────┘
                                                          │
                                          ┌───────────────┴──────────┐
                                          │  qr — the terminal URL   │
                                          └──────────────────────────┘
```

**The rule that keeps this honest:** every arrow crossing into `index` is bytes on disk.
The server never reaches into indexer state, and the indexer never holds a socket. That is
what makes "index in the background while already serving" a five-line change rather than
a rewrite.

## 3. Module tree

Sixteen modules. Each owns one specification and can be tested against an external oracle
without the rest of the program existing.

```
src/
  main.rs             entry, wiring, the two modes
  cli.rs              argument parsing, --help, exit codes
  walk.rs             recursive directory scan, extension filter, symlink policy

  pool.rs             fixed-size worker pool over a shared queue

  jpeg/
    mod.rs            public decode entry
    marker.rs         SOI/APPn/DQT/SOF0/DHT/DRI/SOS/EOI segment walk
    huffman.rs        canonical table construction from BITS/HUFFVAL, decode
    bits.rs           MSB-first bit reader with 0xFF00 unstuffing
    idct.rs           separable 8×8 inverse DCT
    color.rs          dequantise, dezigzag, chroma upsample, YCbCr→RGB

  png/
    mod.rs            encode entry (decode is Stretch)
    chunk.rs          chunk framing, length/type/CRC
    filter.rs         the five scanline filters and the Paeth predictor
    crc.rs            CRC-32/ISO-HDLC, table-driven

  deflate/
    mod.rs            zlib container (RFC 1950)
    lz77.rs           hash-chain match finder
    huffman.rs        static and dynamic code construction
    inflate.rs        the decompressor — built first, used as the test harness

  exif/
    mod.rs            entry: bytes → Meta
    tiff.rs           TIFF header, both byte orders, IFD traversal
    tags.rs           the ~12 tags that matter, GPS rational conversion

  resample.rs         box and bilinear, separable two-pass
  phash.rs            dHash, DCT pHash, Hamming distance, clustering

  index/
    mod.rs            open, query, crash-safe write
    record.rs         the on-disk record layout
    hash.rs           FNV-1a — never DefaultHasher, see §7

  http/
    mod.rs            listener, accept loop, connection lifetime
    request.rs        request line and header parsing
    response.rs       status, headers, body writers
    route.rs          the six routes
    mime.rs           extension → content type
  json.rs             streaming writer, correct escaping. Write-only.

  qr/
    mod.rs            text → module matrix
    gf256.rs          GF(256) arithmetic with the QR primitive polynomial
    rs.rs             generator polynomials, error-correction codewords
    mask.rs           the eight masks and their penalty scoring
    render.rs         terminal half-block output, and qr.png

  net.rs              local IP via the UDP default-route trick
  web/
    index.html        the client, embedded with include_str!
    app.js
    style.css
```

Low-level design per subsystem: `LLD-JPEG.md`, `LLD-DEFLATE-PNG.md`, `LLD-EXIF.md`,
`LLD-PHASH.md`, `LLD-QR.md`, `LLD-HTTP.md`.

## 4. Core contracts

Six type shapes carry the whole program. Signatures only — no bodies.

### 4.1 The image, and what decoders return

```rust
/// 8-bit RGB, tightly packed, no stride padding. The only pixel format in the program.
pub struct Image {
    pub width:  u32,
    pub height: u32,
    pub px:     Vec<u8>,   // len == width * height * 3
}

pub trait Decoder {
    /// Sniff by content, never by extension. `corpus/pathological/` has a `.png`
    /// that is a JPEG and a `.jpg` that is a PNG, and both must work.
    fn probe(head: &[u8]) -> bool;
    fn decode(bytes: &[u8]) -> Result<Image, ImageError>;
}
```

**One pixel format, deliberately.** Every alternative — planar YCbCr, 16-bit, palettes,
alpha — buys nothing darkroom needs and multiplies the conversion matrix between modules.
Alpha is composited onto white at PNG decode time, if PNG decode ships at all.

### 4.2 Metadata

```rust
pub struct Meta {
    pub taken:       Option<i64>,   // seconds since epoch, local wall clock, see §8
    pub make:        Option<String>,
    pub model:       Option<String>,
    pub lens:        Option<String>,
    pub iso:         Option<u32>,
    pub exposure:    Option<(u32, u32)>,   // rational, kept exact — "1/250" not 0.004
    pub f_number:    Option<(u32, u32)>,
    pub orientation: u8,            // 1..=8, defaults to 1
    pub gps:         Option<(f64, f64)>,
    pub dims:        Option<(u32, u32)>,
}
```

`Option` everywhere is the design. **A missing tag is normal, not an error** — most PNGs
have no EXIF at all, and a photo with no `DateTimeOriginal` still belongs in the timeline
under its mtime.

### 4.3 The catalog entry

```rust
pub struct Entry {
    pub id:        u64,      // FNV-1a of the path — stable across runs, see §7
    pub path:      PathBuf,
    pub bytes:     u64,
    pub mtime:     i64,
    pub meta:      Meta,
    pub phash:     u64,      // 0 when the pixels never decoded
    pub dhash:     u64,
    pub thumb:     Option<ThumbRef>,
    pub state:     EntryState,
}

pub enum EntryState {
    Ok,
    /// Catalogued from the container, pixels deliberately not decoded — HEIC.
    NoPreview { reason: &'static str },
    /// Tried and failed. The reason is shown in the UI, not swallowed.
    Failed { reason: String },
}
```

`EntryState` is the honesty mechanism. A file that fails **stays in the timeline with its
reason attached**. Silently dropping unreadable files is how a gallery quietly lies about
what is in the folder.

### 4.4 Work items

```rust
pub struct Job  { pub id: u64, pub path: PathBuf }
pub struct Done { pub entry: Entry, pub elapsed_ms: u32 }

pub trait Pool {
    fn submit(&self, job: Job);
    /// Blocks until every submitted job has been collected.
    fn drain(&self) -> Vec<Done>;
}
```

`elapsed_ms` is carried per job on purpose: the README promises measured throughput
numbers, and a number you have to instrument for later is a number you will not publish.

### 4.5 HTTP

```rust
pub struct Request<'a> {
    pub method:  Method,
    pub target:  &'a str,
    pub headers: Vec<(&'a str, &'a str)>,   // a Vec, not a map — there are ~8 of them
}

pub enum Body {
    Empty,
    Bytes(Vec<u8>),
    Static(&'static [u8]),   // the embedded client — no copy
    File { path: PathBuf, range: Option<(u64, u64)> },
    Stream,                  // SSE — the progress channel
}
```

### 4.6 Errors

One error type per format module, one at the boundary. Every variant names the byte offset
it died at, because "invalid JPEG" is useless in a bug report and `truncated DHT values at
0x2A1` is not — and because the spike proved the specific-diagnostic habit is what makes
adversarial input debuggable in seconds.

```rust
pub enum ImageError {
    NotThisFormat,
    Truncated   { at: usize, expected: &'static str },
    BadField    { at: usize, field: &'static str, value: u32 },
    Unsupported { feature: &'static str },   // progressive, 12-bit, CMYK, HEVC
    TooLarge    { w: u32, h: u32 },
}
```

**`Unsupported` is a first-class outcome, not a failure.** Progressive JPEG and HEIC both
land here and both produce a catalogued entry with a stated reason.

## 5. Concurrency model

Three kinds of thread, and no more.

| Thread | Count | Owns |
| --- | --- | --- |
| Main | 1 | CLI, index lifetime, the QR print, shutdown |
| Indexer workers | `available_parallelism()`, capped at 8 | decode → EXIF → resize → encode → hash |
| HTTP connection | one per accepted connection, capped | one socket, start to finish |

**Blocking IO throughout. No async runtime, and none is missing.** The indexer is
CPU-bound, so threads are exactly the right primitive; the server handles a handful of LAN
clients, where thread-per-connection is correct rather than merely adequate. Say this
plainly in `STDLIB.md` — the substitution being replaced is `tokio`, and the honest cost is
that it would not survive the open internet.

**The connection cap is not optional.** An unbounded accept loop is a thread bomb the first
time a phone browser opens six parallel connections for a grid of thumbnails and then the
user pulls to refresh. Cap it, and return `503` with `Retry-After` past the cap.

**Ordering.** `Pool::drain` collects into submission order, so two runs over the same
folder produce the same catalog in the same order. Non-deterministic ordering makes
the index diff-hostile and makes bugs unreproducible.

**The one shared mutable thing** is the progress counter — an `AtomicU64` pair (`done`,
`total`) read by the SSE route. No lock, no channel, no ordering requirement beyond
`Relaxed`, because it drives a number on a web page.

## 6. Data flow

### 6.1 Indexing one file

```
path
 ├─ read bytes                                        (io)
 ├─ probe magic ────────────────► JPEG / PNG / GIF / HEIC / other
 ├─ exif::parse(bytes)  ──────────► Meta               (never fatal)
 ├─ decode ─────────────────────► Image                (may be Unsupported)
 ├─ apply Meta.orientation ─────► Image                (before anything else)
 ├─ resample to 256px long edge ► Image
 ├─ png::encode ────────────────► Vec<u8>              (via deflate)
 ├─ phash + dhash on a 32×32 grey reduction of the *decoded* image
 └─ Entry ──────────────────────► index
```

**Orientation is applied before the thumbnail and before the hash.** Miss it and a portrait
photo shot on a phone thumbnails sideways *and* fails to cluster against its own rotated
copy — one bug that shows up as two unrelated ones.

**EXIF is parsed before the pixels and never blocks on them.** That is what lets HEIC
files carry real dates into the timeline while the pixel path returns `Unsupported`.

### 6.2 Serving a request

```
accept ─► parse request line + headers ─► route
                                            ├─ GET  /              → Static(index.html)
                                            ├─ GET  /app.js|css    → Static
                                            ├─ GET  /api/photos    → json from index
                                            ├─ GET  /thumb/{id}    → Bytes from index
                                            ├─ GET  /orig/{id}     → File + Range
                                            └─ GET  /api/progress  → Stream (SSE)
                                          ─► conditional GET check (ETag)
                                          ─► write response
                                          ─► keep-alive or close
```

`/thumb/{id}` never touches the filesystem — the thumbnail bytes live in the index. That is
the single decision that makes a grid of 200 thumbnails fast on a phone over Wi-Fi.

## 7. The index — on-disk format

Own format, documented, versioned. ~400–600 lines including the writer.

```
magic       "DKRM"                 4 bytes
version     u32 LE                 bump on any layout change; refuse mismatches loudly
root_hash   u64                    FNV-1a of the canonical root path
count       u64
entries[]   length-prefixed records, see LLD note below
thumbs[]    concatenated PNG bytes, addressed by (offset, len) from the record
```

**Crash safety: temp file → write → `sync_all()` → `rename()`.** `rename` over an existing
file is atomic on Windows and POSIX alike. Without `sync_all` the rename can land before
the data does and a power cut leaves a valid-looking index full of zeros — which is worse
than no index, because it does not retry.

**Two rules with teeth:**

- **FNV-1a, never `DefaultHasher`.** `std`'s `DefaultHasher` is `RandomState`-seeded and
  **not stable across runs or across releases**. Persisting one of its outputs produces an
  index that silently fails to match itself on the next launch. This is the single easiest
  way to lose a day.
- **Never trust the version field to be the only guard.** Records carry their own length,
  so a truncated index is detected at the record that runs off the end rather than by
  reading garbage into a `u64`.

**Staleness.** An entry is reused when `(path, bytes, mtime)` all match. Anything else is
re-indexed. Content hashing every file to detect changes costs a full read of the folder
and buys almost nothing over mtime for photos, which are written once.

## 8. Time, without a time library

`std` gives `SystemTime` — seconds since the epoch — and nothing else. No dates, no
formatting, no zones.

- **Howard Hinnant's `days_from_civil` / `civil_from_days`**, ~40 lines, exact both ways
  across the full proleptic Gregorian range. This is the whole calendar layer.
- **EXIF `DateTimeOriginal` is local wall-clock time with no zone**, which is a gift: it
  gets stored as-is and displayed as-is, and no zone database is needed anywhere.
- **The honest cost, for the README:** a photo taken abroad sorts by the camera's clock,
  not yours. Stated, not hidden.

## 9. Never panic

The spike measured **zero panics across 23 adversarial files**, and that number is a README
claim, so the design has to keep earning it.

- Every read from a byte slice goes through a checked cursor that returns `Truncated`, not
  through `&bytes[i..j]`.
- Every length and dimension from a file is validated **before** it is used to allocate.
  A 20000×150 panorama is legitimate; a header claiming 65535×65535 is 12 GB and must be
  refused by `TooLarge`, not attempted.
- Arithmetic on file-supplied values is checked. Huffman code lengths, IFD offsets and
  DEFLATE distances are all attacker-controlled in the practical sense.
- `catch_unwind` at the worker boundary as a last resort, so one bad file marks itself
  `Failed` and the other 3,000 still index.

### 10.2 ⚠️ The 1,000-line gap — unresolved

The halved list sums to **5,000**; it was sold as **4,000**. That gap is a full day and it
has never been closed. **It must be closed before darkroom is ever chosen**, not during.
The candidates, in the order they should go:

1. **QR → −350.** Print the URL as text. Costs the demo's best-known beat; saves the whole
   Reed–Solomon module. *(But see the note in `LLD-QR.md` — this is also the most
   distinctive craft in the project, so cutting it is not free on the 30% criterion.)*
2. **Thread pool → −150.** Fixed thread count, chunked work ranges, no queue.
3. **Web UI 500 → 300.** Grid and detail view only; drop the cluster view's animation.
4. **Index 400 → 250.** No thumbnail store; regenerate on demand and cache in memory.

Any three of those close it. **Deciding which three is the first thing to do if darkroom is
revived** — see `README.md` open decisions.

## 11. Build order — the ladder

The schedule (`SCHEDULE-72H.md`) is organised as **rungs**, not modules, and this is the
most important structural decision in the plan: **every rung is independently submittable.**
A finished rung 3 beats a half-finished rung 5 that does not build.

| Rung | What works | Depends on |
| --- | --- | --- |
| **R0** | repo, empty manifest, `--help`, first commit | — |
| **R1** | **browse a real photo folder from your phone** — originals served, browser decodes | cli, walk, http, pool, web |
| **R2** | **thumbnails decoded by our own code** | jpeg, resample, deflate, png, crc |
| **R3** | **sorted by the date actually taken** | exif, index |
| **R4** | **it finds your duplicates** | phash |
| **R5** | **the QR moment — feature complete** | qr, net |

**R1 ships before a single line of codec exists**, because the browser can decode JPEG
itself. That is the insurance policy: three hours in, there is already an artifact that
satisfies the deliverables. Everything after R1 is upside.

**Commit and push at every rung.** The ladder is only insurance if it is climbed one rung
at a time.

## 12. What `std` withholds, and the answer

The 30% criterion is scored on exactly this table. Full rationales with costs are in
`STDLIB.md` (14 substitutions).

| Missing | Consequence | Answer | Verdict |
| --- | --- | --- | --- |
| Local IP address | Cannot tell the phone where to go | **UDP default-route trick** — bind `0.0.0.0:0`, `connect()` to a routable address, read `local_addr()`. Proven on this machine | ✅ solved |
| Randomness | No RNG of any kind | Entropy out of a freshly built `RandomState`. Used for ETag salts, nothing security-critical, and the README says so | ✅ solved |
| `SO_REUSEADDR` | **mDNS on 5353 is not reliably possible** beside a running Bonjour/avahi | Do not use mDNS. The QR carries a raw IP and port and needs no discovery at all | ⚠️ designed around |
| TLS | No HTTPS, ever | LAN-only plain HTTP. File inputs and form POST work over insecure origins; only camera/geolocation would not | ⚠️ scoped out |
| `mmap` | Large-file random access via seek/read | `Seek` plus a small page cache. Slower — publish the number | ✅ solved |
| `flock` | Two instances could corrupt the index | Lockfile via `OpenOptions::create_new(true)`, atomic everywhere. Stale-lock detection by PID | ✅ solved |
| Calendar time | `SystemTime` gives seconds and nothing else | Hinnant's algorithm, ~40 lines, exact — see §8 | ✅ solved |
| Compression, CRC, hashing | No DEFLATE, no zlib, no CRC32 | Implement them. Required for PNG regardless, short, frozen, trivially verifiable | ✅ **and it is the point** |
| Raw terminal input | No termios, no console API | Not needed. The interface is a browser; the terminal only prints | ✅ n/a |

## 13. The one thing that will not be attempted

**HEIC / HEVC pixel decoding.** The container is ordinary ISOBMFF and parses in a few
hundred lines. The image inside is HEVC intra-coded: CABAC arithmetic decoding, quadtree
CTU partitioning, thirty-five intra prediction modes, deblocking, SAO. That is several
thousand lines of bit-exact code that **fails silently when it is subtly wrong** — the
worst possible failure mode inside a 72-hour window.

**What ships instead:** HEIC files are catalogued from the container. Date, camera,
dimensions and GPS all read correctly, the file appears in the timeline in the right place,
and the tile shows *preview unavailable — HEVC*.

This is a design decision with a stated reason, not a gap. It is in the README, it is in
`STDLIB.md` under "deliberately not attempted", and it is said out loud in the demo at
4:30 — because the alternative is a judge holding an iPhone discovering it at 1:15.
