# Demo script — 5 minutes

---

## 0:00–0:20 · Cold open, no narration

One command: `darkroom ~/Pictures`. A QR code paints in the terminal. A hand lifts a phone, scans
the screen, and a photo library fills it.

**Film the phone with a camera. Do not screen-record it.** A real device in a real hand reading a
QR off your actual monitor is unfakeable in a way a screen capture never is.

No explanation yet. Show the destination before asking anyone to walk there.

## 0:20–0:50 · The manifest, in one unbroken take

```
cat Cargo.toml        →  [dependencies] with nothing under it
cargo tree            →  one node
cat deps-proof.txt
```

**Do not cut during this.** It is the one place an audience's suspicion has somewhere to go, and
holding the shot costs nothing.

## 0:50–1:40 · Prove it is a real tool

Point it at a folder with thousands of actual photos, not twelve samples. Let the indexer run.
Show honest timing on screen. This is where a judge decides whether you built a tool or a demo.

Cut away to code while it runs — never sit on a progress bar.

## 1:40–2:40 · The payload: duplicates

The beat people remember, because it is the thing they cannot do by hand.

- A burst of eight near-identical shots collapsing into one cluster
- The same photo at three resolutions and one re-encode, all recognised as the same photo
- A reclaimed-space number at the end

Perceptual hashing is invisible engineering until you show it *finding* something.

## 2:40–4:00 · Lift the lid

The conversion from "nice gallery" to "engineering marvel". It has to be explicit or it does not
land.

Cut to source: the Huffman decoder, the IDCT, the DEFLATE encoder, the Reed–Solomon generator.
One line of narration does the work:

> "The browser never decoded that thumbnail. This did."

Then the module tree with line counts beside it.

**The quiet kill:** the QR code that phone scanned at 0:15 was generated by the Reed–Solomon code
now on screen. The opening shot was already the proof.

Twenty seconds per file, maximum. Do not linger.

## 4:00–4:30 · The kill list

On screen with weekly download counts (**verify the numbers first**):

`sharp` · `qrcode` · `exifread` · `imagehash` · `tokio` · `axum` · `rayon` · `flate2` · `walkdir`

That is the Package Killer bonus, claimed visually.

## 4:30–4:50 · Say the limits out loud

- HEIC does not decode, and the one-sentence reason why
- Real throughput numbers, including the slow one
- Thread-per-connection, LAN-only, no TLS

Almost nobody does this in a demo, which is exactly why it reads as confidence. This event's
rubric explicitly rewards honest numbers.

## 4:50–5:00 · Close on the empty manifest

The phone opened it, the manifest closes it. **Do not repeat the phone shot** — you already spent
it.

## Pre-flight before recording

- [ ] Firewall prompt already accepted (done in preflight, 2026-08-16)
- [ ] Phone and laptop on a network **without AP isolation** — verified via `192.168.0.105:8080`
- [ ] Demo folder curated: **JPEG only**, so HEIC never appears on screen uninvited. You disclose
      it at 4:30 on your own terms; a judge discovering it at 1:15 is a different thing entirely.
- [ ] Demo folder contains a genuine near-duplicate set — same shot at two resolutions. Exact
      duplicates are unremarkable; near-duplicates are the thing people cannot do themselves.
- [ ] Terminal QR contrast checked against a phone camera
- [ ] `qr.png` written to disk as the fallback path
- [ ] Notifications off, screen at a readable resolution, terminal font large

## What kills demos at this length

Dead air during indexing. Narrating over a static terminal. Lingering on source. And the fatal
one: **forgetting the manifest shot**, which is a required deliverable, not a flourish.
